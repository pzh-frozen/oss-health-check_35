# 常见问题（FAQ）

## 安装与运行

**Q：需要什么版本的 Python？**

A：3.11 及以上。项目用 `tomllib` 解析配置，3.10 及更早版本没有标准库 TOML 解析器。

**Q：能离线使用吗？**

A：可以。`oshc` 只读取本地目录，不发起任何网络请求，不执行被检查项目的代码。

**Q：为什么 `oshc` 命令找不到？**

A：确认已经 `pip install -e .`，并且当前 Python 环境的 Scripts 目录在 PATH 中。
临时替代方案是 `python -m oshc scan .`。

**Q：支持 Windows 吗？**

A：支持。路径比较不区分大小写，输出使用 UTF-8；如果终端出现乱码，把编码切到
UTF-8（`chcp 65001`）即可。

## 评分规则

**Q：为什么我的仓库有 README，却只拿到「警告」？**

A：README 检查同时看两件事：正文有效字符数（≥ 800）与结构章节（安装、使用、
许可证、贡献四类至少命中三类）。只有标题没有内容的 README 会被判为「缺失」。

**Q：为什么跳过项不扣分？**

A：因为「这项不适用于本仓库」不应被当作缺陷。但跳过项会明确列在报告里，
避免用忽略来刷分；同时跳过项不进入分母，所以也不会拉低总分。

**Q：总分 85 分算好吗？**

A：85 分以上是「优秀 A」，通常意味着社区文档与工程实践都比较完整。
但分数只是起点：13 项检查覆盖的是「开源的公共礼仪」，代码质量与文档深度
需要人工判断。

**Q：可以只检查部分项吗？**

A：可以。在 `.oshc.toml` 的 `[ignore] checks` 中列出要跳过的 id，或调整 `[weights]`
把不关心的项权重调低。`oshc checks` 可以查看全部 id。

## 配置

**Q：配置文件放在哪里？**

A：默认查找仓库根目录的 `.oshc.toml`，找不到再找当前工作目录下的同名文件。
也可以用 `--config path/to/file.toml` 显式指定，或用 `--no-config` 忽略配置。

**Q：命令行参数和配置文件冲突时谁优先？**

A：命令行优先。例如 `--fail-under 90` 会覆盖配置文件里的 `fail_under = 80`。

**Q：权重需要凑到 100 吗？**

A：不需要。评分时会按参与计算的总权重归一化，你只需要表达相对重要性。

## CI 集成

**Q：如何在 PR 中自动跑评分？**

A：在流水线中加入：

```yaml
- run: python -m oshc scan . --fail-under 80
```

低于阈值会返回退出码 1，PR 检查会变红。若想只提示不阻塞，去掉 `--fail-under` 即可。

**Q：能让评分卡自动写进 PR 评论吗？**

A：v0.5.0 的计划是用 GitHub Action 封装。目前可以先用 `--markdown` 生成报告，
再配合 `peter-evans/create-or-update-comment` 之类的 Action 贴到 PR 中。

## 其他

**Q：会支持扫描远程仓库吗？**

A：计划在 v0.4.0 支持 `--repo owner/name`，通过 GitHub API 读取文件树。
当前请先 `git clone` 到本地再扫描。

**Q：如何新增一个检查项？**

A：见 [CONTRIBUTING.md](../CONTRIBUTING.md) 的「新增一个检查项」一节，
以及 [architecture.md](architecture.md) 的模块说明。

**Q：发现误报怎么办？**

A：请用「缺陷报告」模板提交，附上最小复现目录结构。误报会优先修复，
因为错误的评分比没有评分更伤信任。
